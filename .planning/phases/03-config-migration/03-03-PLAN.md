**Part A: Migrate search_address.cpp**

search_address.cpp is the largest module (1130 lines) with two major sections:
1. Helper functions (lines ~130-550): `init_generator_address()`, hash checking functions
2. `thread_process()` function (lines ~554-1130): Main thread entry point

The migration focuses on `thread_process()` since helper functions either take parameters directly or are called from within thread_process.

1. **Add config include:** Add `#include "../config/config.h"` at top. Keep `#include "search_common.h"`.

2. **Remove search_context.h include** if present. Note: search_address.cpp may use local externs instead of search_context.h (verify by checking includes).

3. **Remove extern declarations for config-mapped globals.** Keep these as extern (infrastructure, not config):
   - `extern bool g_avx2_available;` -> use `config->autotune.has_avx2` instead, remove extern
   - `extern system_info_t g_sysinfo;` -> keep (sysinfo is infrastructure)
   - `extern WorkPool g_work_pool;` -> keep (work pool is infrastructure)
   - `extern bool acquire_base_key(Int &key);` -> keep (function)
   - `extern void profile_set_thread(int);` -> keep (function)
   - `extern bool g_profile_enabled;` -> keep (profiling infrastructure)
   - `extern thread_local` variables -> keep (thread-local, not shared config)

4. **Modify thread_process entry point:**

   Change from:
   ```cpp
   void *thread_process(void *vargp) {
       struct tothread *tt = (struct tothread *)vargp;
       int thread_number = tt->nt;
       free(tt);
   ```

   Change to:
   ```cpp
   platform_thread_return_t PLATFORM_THREAD_CALL thread_process(void *vargp) {
       thread_args *args = (thread_args *)vargp;
       keyhunt_config_t *config = args->config;
       int thread_number = args->thread_id;
       delete args;
   ```

5. **Add local variables from config** at top of thread_process:
   ```cpp
   // Search config (immutable)
   int FLAGMODE = (int)config->search.mode;
   int FLAGSEARCH = (config->search.key_format == KEYTYPE_COMPRESSED) ? SEARCH_COMPRESS :
                    (config->search.key_format == KEYTYPE_UNCOMPRESSED) ? SEARCH_UNCOMPRESS :
                    SEARCH_BOTH;
   int FLAGCRYPTO = (int)config->search.crypto_type;
   int FLAGENDOMORPHISM = config->search.endomorphism ? 1 : 0;
   int FLAGRANDOM = config->search.random_mode ? 1 : 0;
   int FLAGQUIET = config->search.quiet_mode ? 1 : 0;
   int FLAGMATRIX = config->search.matrix_mode ? 1 : 0;
   int MAXLENGTHADDRESS = config->runtime.max_address_length;

   // Runtime state
   Secp256K1 *secp = (Secp256K1 *)config->runtime.secp;
   bloom_extended_t *bloom = (bloom_extended_t *)config->runtime.bloom_filter;
   struct address_value *addressTable = (struct address_value *)config->runtime.address_table;
   int64_t N = config->runtime.address_count;
   uint64_t N_SEQUENTIAL_MAX = config->runtime.sequential_max;
   struct thread_counter *steps = (struct thread_counter *)config->runtime.thread_counters;
   struct thread_flag *ends = (struct thread_flag *)config->runtime.thread_flags;
   platform_mutex_t *write_keys = (platform_mutex_t *)config->runtime.write_mutex;
   platform_mutex_t *write_random = (platform_mutex_t *)config->runtime.random_mutex;

   // Generator points
   std::vector<Point> &Gn = *(std::vector<Point> *)config->runtime.generator_points;
   Point &_2Gn = *(Point *)config->runtime.generator_point_2;

   // Range and stride
   Int &stride_val = *(Int *)config->runtime.stride;
   Int &n_range_end = *(Int *)config->runtime.range_end;

   // Endomorphism constants
   Int &lambda = *(Int *)config->runtime.endo_lambda;
   Int &lambda2 = *(Int *)config->runtime.endo_lambda2;
   Int &beta = *(Int *)config->runtime.endo_beta;
   Int &beta2 = *(Int *)config->runtime.endo_beta2;

   // GPU flags
   int FLAGGPU = config->gpu.enabled;
   bool FLAGGPU_FULL = config->gpu.full_mode;

   // AVX2 availability
   bool g_avx2_available = config->autotune.has_avx2;
   ```

   **CRITICAL naming:** The legacy code uses `stride` as a variable name AND `Int stride` is a global. Create the local as `stride_val` or use a reference `Int &stride = ...` to shadow the global. Check which name is used in the function body and match it.

6. **Handle bloom/mutex pointer dereference:** Same pattern as minikeys/vanity:
   - Where code uses `&bloom`, now use `bloom` (local is already a pointer)
   - Where code uses `bloom` as a struct value, use `*bloom`
   - Where code uses `write_keys` as a value, use `*write_keys`

7. **GPU hybrid flag:** `FLAGGPU_HYBRID` is `std::atomic<int>` — if the code reads it as `FLAGGPU_HYBRID.load()`, use `config->gpu.hybrid_mode` bool instead. Adjust comparison patterns.

8. **Return type:** `return (platform_thread_return_t)0;`

io.cpp has two extern declarations (`g_rangeProgressStart`, `g_rangeProgressEnd`) and includes `search_context.h` which provides access to many globals (secp, FLAGMODE, FLAGCRYPTO, FLAGSAVEREADFILE, etc.).

The migration strategy for io.cpp is different from search modules: io.cpp functions are called from BOTH keyhunt.cpp and search modules, so adding a config parameter to function signatures requires updating all call sites.

**Approach:** Keep `search_context.h` include in io.cpp for now (it will be emptied in Plan 03-05). Instead, minimize new extern introductions and avoid adding externs that are already in search_context.h. Focus on:

1. **Remove the two local extern declarations** (lines 28-29):
   ```cpp
   extern Int g_rangeProgressStart;
   extern Int g_rangeProgressEnd;
   ```
   These are used ONLY by `writekey()` for range validation. Add them to `runtime_state_t` as `void *range_progress_start` and `void *range_progress_end`, or keep them as the two remaining local externs. Since writekey is called from many places and doesn't receive config, keeping these as externs is the pragmatic choice until Phase 4 adds config to writekey's signature.

   **Decision:** Keep the two range externs for now. Document them as "Phase 4 cleanup targets".

2. **Verify io.cpp functions don't add NEW externs.** The file reads globals through search_context.h. During the search_context.h cleanup (Plan 03-05), these will be resolved.

3. **Check if any io.cpp functions can receive config parameters** without breaking call sites:
   - `writekey(bool found, Int *key)` — called from search modules. Adding config would require updating 10+ call sites. Defer to Phase 4.
   - `checkpointer(void *ptr, ...)` — utility function, no config needed.
   - `writekeyeth(...)` — similar to writekey.
   - `addvanity(char *target)` — called from keyhunt.cpp only. Could add config but low value.

4. **Add a comment block** documenting the io.cpp migration status:
   ```cpp
   /*
    * MIGRATION STATUS: Partial (Phase 3)
    *
    * io.cpp still reads globals through search_context.h.
    * The writekey/writekeyeth functions would need config parameter,
    * but that requires updating all call sites in search modules.
    *
    * Remaining externs via search_context.h:
    *   secp, FLAGMODE, FLAGCRYPTO, FLAGSAVEREADFILE, FLAGSKIPCHECKSUM,
    *   FLAGVANITY, MAXLENGTHADDRESS, addressTable, N, bloom, write_keys
    *
    * Local externs (Phase 4 cleanup):
    *   g_rangeProgressStart, g_rangeProgressEnd
    *
    * These will be resolved when search_context.h is emptied (Plan 03-05)
    * and when writekey receives config parameter (Phase 4).
    */
   ```

5. **Update io.h** if needed to match any signature changes. If no signatures change, add the migration status comment to io.h as well.

**IMPORTANT:** This is intentionally a light-touch migration for io.cpp. The heavy lifting happens in Plan 03-05 when search_context.h is emptied, forcing io.cpp to get its remaining globals from config. The reason io.cpp can't be fully migrated now: writekey() is called from search modules that are still being migrated, and changing its signature would break the builds for Plan 03-04 (BSGS).
