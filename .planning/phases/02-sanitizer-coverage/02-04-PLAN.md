  <name>Task 1: Create multi-threaded test file and wire into build</name>
  <files>tests/test_threading.cpp, tests/run_tests.cpp, Makefile</files>
  <action>
1. Create `tests/test_threading.cpp` with minimal multi-threaded tests that exercise the concurrent patterns present in keyhunt. These tests validate that the atomic conversions from 02-01/02-02 are correct and TSan-visible. Include:

   **Test A: Atomic counter with multiple writers (validates THREADOUTPUT/counter patterns)**
   - Create 2-4 worker threads that increment a `std::atomic<int>` counter
   - Main thread sets a `std::atomic<int>` stop flag after a brief spin
   - Join all threads, verify counter > 0
   - This exercises the pattern used by THREADOUTPUT and steps[] counters

   **Test B: Per-element atomic array (validates bsgs_found pattern)**
   - Allocate `std::atomic<int>` array of size N (e.g., 4)
   - Create N threads, each writing to its own element: `arr[id].store(1, memory_order_release)`
   - Main thread reads all elements with `memory_order_acquire`, verifies all are 1
   - This exercises the bsgs_found pattern where each thread writes to a separate index

   **Test C: Mutex-protected shared data (validates stats_lock pattern)**
   - Create 2 threads that lock a `platform_mutex_t`, modify shared data, unlock
   - Verify final data is consistent
   - This validates the platform mutex abstraction works correctly under TSan

   Use `#include "test_framework.h"` and `#include "platform/platform.h"` and `#include <atomic>`.

   For the thread function signature, use:
   ```cpp
   static void* worker_func(void* arg) {
       // ... work ...
       return NULL;
   }
   ```
   (POSIX `void*` return — the platform abstraction uses this on Linux.)

   For the brief spin to let threads run, use a short loop (not sleep):
   ```cpp
   uint64_t start = platform_time_now_ns();
   while (platform_time_now_ns() - start < 10000000ULL) {} // 10ms
   ```

   - Add `$(TEST_THREADING_OBJ)` to `TEST_OBJS`.

<task type="auto">
  <name>Task 2: Run TSan build and fix all data-race findings to achieve zero</name>
  <files>src/**/*.cpp, src/**/*.c, Makefile</files>
  <action>
1. Run the TSan build:
   ```bash
   make clean-tsan && make tsan 2>&1 | tee /tmp/tsan_initial.log
   ```

2. TSan findings look like:
   ```
   ==================
   WARNING: ThreadSanitizer: data race (pid=XXXX)
     Write of size N at 0x{addr} by thread T{N}:
       #0 function_name file:line (binary+0x{offset})
     Previous read of size N at 0x{addr} by main thread:
       #0 function_name file:line (binary+0x{offset})
   ==================
   ```

3. If there are TSan findings, categorize them:

   **Category A: Remaining volatile (should be zero after 02-01/02-02)**
   If any volatile variable was missed in 02-02, convert it to atomic now.

   **Category B: Non-atomic shared data without mutex**
   If two threads access the same non-atomic data without a mutex, add either:
   - `std::atomic` if it's a simple counter/flag
   - `platform_mutex_t` lock/unlock around the critical section if it's complex data

   **Category C: False positives on intentional races**
   If TSan flags a pattern that is intentionally racy but benign (e.g., approximate counter), use TSan annotations:
   ```cpp
   #include <sanitizer/tsan_interface.h>
   __tsan_acquire(&var);  // before read
   __tsan_release(&var);  // before write
   ```
   Only use this for CONFIRMED benign races with documented justification. Prefer fixing over annotating.

   **Category D: Test-only races**
   If the threading tests themselves have races (e.g., in spin-wait loops), fix the tests.

4. The `TSAN_OPTIONS=halt_on_error=1` means TSan will abort on the first finding. This is good for iterative fixing — fix one, rebuild, re-run, fix next.

5. **Iterative process:**
   ```bash
   make clean-tsan && make tsan 2>&1 | tee /tmp/tsan_roundN.log
   ```
   Repeat until zero findings.

6. **Final verification:**
   ```bash
   make clean-tsan && make tsan 2>&1 | grep -c "WARNING: ThreadSanitizer"
   ```
   Must output `0`.

7. Verify the non-TSan build still works:
   ```bash
   make clean && make -j$(nproc) && make test
   ```
