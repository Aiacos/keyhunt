**Step 3: Fix test_intgroup.cpp (11 failures)**

Root cause: Tests verify `original * inverse == 1` using `ModMulK1()` which does lazy reduction (result may be congruent to 1 mod P but not exactly 1 in internal representation).

For each ModInv test (10 of 11 failures):
- After computing `result = original.ModMulK1(&inverse)`, add a normalization step before checking IsOne()
- Normalization: If result >= P (the secp256k1 field prime), subtract P. The field prime P = `FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEFFFFFC2F`
- Alternative approach: Use `result.IsEqual()` against a known 1 value, or check `result.IsStrictlyOne()` after calling `result.ModSub(&result, &P)` when `result >= P`
- Best approach per research: Instead of `ModMulK1`, use `ModMul()` (Montgomery-based, fully reduces) for the verification step. Change the test verification to use `original.ModMul(&inverse)` instead of `original.ModMulK1(&inverse)`

For the `modular_arithmetic_modadd_overflow` failure (1 of 11):
- Debug the specific case: `ModAdd(P-1, 10)` should equal `9`
- If ModAdd only subtracts P once and the result is correct mathematically, the test expectation may need adjustment
- Trace through the actual ModAdd implementation to verify
