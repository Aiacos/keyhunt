# Vanity Mode

Vanity mode generates Bitcoin addresses with custom prefixes (vanity addresses).

## Overview

| Aspect | Details |
|--------|---------|
| Command | `-m vanity` |
| Input | Desired address prefix |
| Purpose | Generate addresses starting with custom text |
| Example | `1Love...`, `1Cat...`, `1BTC...` |

## How It Works

1. **Random Key Generation**: Generate random private keys
2. **Address Derivation**: Compute Bitcoin address from each key
3. **Prefix Matching**: Check if address starts with desired prefix
4. **Output**: Save matching key and address

## Basic Usage

```bash
./keyhunt -m vanity -v 1Love
```

## Vanity Prefix Rules

Bitcoin addresses follow Base58Check encoding rules:

### Valid Characters
```
123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz
```

**Not allowed**: `0`, `O`, `I`, `l` (zero, uppercase O, uppercase I, lowercase L)

### First Character
- **1**: Legacy P2PKH (pay-to-public-key-hash)
- **3**: P2SH (pay-to-script-hash)
- **bc1**: Bech32 (SegWit) - not supported in vanity mode

### Difficulty Scaling

Each additional character increases difficulty by ~58x:

| Prefix Length | Approximate Difficulty | Time (100 Mkeys/s) |
|---------------|------------------------|-------------------|
| 1Love | 4 chars after 1 | ~11 million keys | < 1 second |
| 1Loves | 5 chars after 1 | ~656 million keys | ~7 seconds |
| 1LovesY | 6 chars after 1 | ~38 billion keys | ~6 minutes |
| 1LovesYou | 8 chars after 1 | ~128 trillion keys | ~15 days |

## Parameters

### Vanity Prefix (`-v`)

```bash
./keyhunt -m vanity -v 1BTC
```

### Key Type (`-l`)

```bash
# Compressed addresses (shorter, modern)
./keyhunt -m vanity -v 1Love -l compress

# Uncompressed (legacy)
./keyhunt -m vanity -v 1Love -l uncompress
```

### Thread Count (`-t`)

```bash
./keyhunt -m vanity -v 1Love -t 16
```

## Example Scenarios

### Simple 4-Character Vanity

```bash
./keyhunt -m vanity -v 1Cat -t 8 -l compress
```

### Case Sensitivity

Vanity matching is case-sensitive:
```bash
./keyhunt -m vanity -v 1LOVE    # Different from 1Love
```

### Multiple Attempts

For longer prefixes, run on multiple machines or use GPU:
```bash
./keyhunt -m vanity -v 1Loves -t 32 -G hybrid
```

## Security Considerations

### Generated Keys are Cryptographically Random

Vanity addresses are just as secure as regular addresses - the search finds random keys that happen to produce matching prefixes.

### Beware of Vanity Address Scams

Never use a vanity address generated by someone else. They may have kept the private key.

### Verify Before Use

Always verify you have the private key and can sign transactions before receiving funds.

## Practical Limits

| Prefix | Feasibility |
|--------|-------------|
| 1-5 chars | Easy (seconds to minutes) |
| 6 chars | Moderate (minutes to hours) |
| 7 chars | Difficult (hours to days) |
| 8+ chars | Very difficult (days to months) |

For very long prefixes, consider GPU acceleration or distributed computing.

## GPU Acceleration

For faster vanity generation:

```bash
./keyhunt -m vanity -v 1LovesYou -G hybrid -t 16
```

## Use Cases

1. **Personal branding**: `1YourName...`
2. **Business identity**: `1CompanyName...`
3. **Memorable addresses**: `1Bitcoin...`
4. **Donation addresses**: `1Donate...`

## Limitations

- Only P2PKH addresses (starting with 1)
- No Bech32 (bc1...) vanity support
- Difficulty scales exponentially
- Case-sensitive matching only
